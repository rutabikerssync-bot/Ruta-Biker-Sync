4) Interpretación
- El temporizador de pérdida (`LOST_TIMEOUT_MS = 40_500 ms`) no produjo falsos `isLost`:
  el peer BLE permaneció conectado y con heartbeats durante los 35 min. En esa capa,
  FIX B se comporta como fue diseñado.
- La oscilación visible del HUD NO es inestabilidad BLE. El conteo del HUD se calcula
  en `LiveMapViewModel.kt:619-621` sobre marcadores, y `HybridTransportDispatcher.fuse()`
  recibe `resolveShortId = { null }` (`LiveMapScreen.kt:475`), así que cada muestra HTTP
  obtiene un shortId sintético 60000+ aunque el mismo rider ya esté en BLE. Esos marcadores
  [4G] extra se añaden y se retiran por TTL de 30 s, produciendo 3 → 2 → 1 → 3.
- Por tanto NO se afirma que el criterio de usuario «2 riders estables» esté verificado.
  Se afirma únicamente que la capa BLE estuvo estable.
