BLOQUE A — DIAGNÓSTICO Y RECUPERACIÓN DE FASTIFY — 2026-11-18
================================================================

CONCLUSIÓN
----------
Fastify NO estaba caído: el proceso seguía vivo en WSL2 y /health respondía 200.
El banner rojo de la app era un problema de configuración del cliente Android:
la build debug usaba BASE_URL=http://127.0.0.1:3000, pero el networkSecurityConfig
de main (cleartextTrafficPermitted=false) prevalecía sobre usesCleartextTraffic=true
del manifest debug. La app fallaba con:
  🔴 Fastify offline (Cleartext HTTP traffic to 127.0.0.1 not permitted)

Se corrigieron dos cosas:
  1. backend/src/db/pool.ts ahora registra 0015_add_mf_tier.sql y 0016_club_profile.sql
     (defecto latente: en una BD limpia faltarían columnas de identidad de club).
  2. Cliente debug: BASE_URL parametrizable (-Prbs.debug.url / RBS_DEBUG_URL) y overlay
     android/app/src/debug/res/xml/network_security_config.xml solo para debug.
     Release conserva TLS obligatorio.
