ARQUITECTURA
------------
WSL Ubuntu (PostgreSQL 16 + Fastify `npm run dev` en 0.0.0.0:3000)
  -> wslrelay de Windows expone 127.0.0.1:3000
  -> `tailscale serve` publica `/` como https://omartinezpaz.tail6f67b0.ts.net
  -> los dos Android resuelven el nombre Tailscale y llegan por HTTPS
  -> la app debug lleva BASE_URL=https://omartinezpaz.tail6f67b0.ts.net

No hay `adb reverse` activo en ninguno de los dos dispositivos. Los equipos
estan en LANs distintas (192.168.1.x y 192.168.100.x) y Tailscale los une en
la tailnet 100.64.0.0/10.

CONFIRMACION
------------
Los dos equipos estan conectados a Tailscale y Fastify responde por HTTPS a
traves de la tailnet sin cable USB y sin estar en la misma red. La app usa esa
misma URL y muestra el banner verde de health en ambos dispositivos. Si el
proceso de Fastify muere, systemd lo reinicia solo (probado con NRestarts=1).
Si Windows se reinicia, el script de Inicio levanta WSL y el servicio systemd
ya habilitado levanta Fastify; Tailscale y su `serve` quedan en la config del
daemon y se restauran al iniciar sesion.

CONFIGURACION FUERA DEL REPOSITORIO (no versionable)
----------------------------------------------------
- /etc/systemd/system/rbs-backend.service en WSL (User=ozmar, WorkingDirectory=
  /mnt/d/Ruta-Biker-Sync/backend, ExecStart=/usr/bin/npm run dev,
  Restart=always, RestartSec=5). Habilitado con `systemctl enable --now`.
- %APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\rbs-wsl-backend.vbs
  con `ws.Run "wsl.exe -e true", 0, False`.
- `tailscale serve --https=443 / http://127.0.0.1:3000` (ya persistido por
  Tailscale; verificado con `tailscale serve status --json`).
- Android: always_on_vpn_app=com.tailscale.ipn, always_on_vpn_lockdown=0 y
  Tailscale en la whitelist de deviceidle.

PENDIENTE
---------
- No se pudo crear una tarea programada de Windows con `schtasks /create`
  porque requiere elevacion (acceso denegado); se uso el script de Inicio del
  usuario, que no necesita admin. Si el equipo usa autologon o se bloquea la
  pantalla antes de cargar el Inicio, validar el arranque en ese escenario.
- No se probe un reinicio completo de Windows (requiere intervencion fisica).
  La cadena WSL -> servicio systemd -> tailscale serve quedo configurada y
  cada eslabon se verifico por separado.
- El ping Redmi -> TECNO por IP Tailscale devolvio 100% de perdida una vez,
  mientras TECNO -> Redmi y ambos -> Windows funcionaron. La comunicacion
  moto a moto sigue por BLE; no se investigo mas porque no afecta a Fastify.
- El build debug se regenero con RBS_DEBUG_URL; si se recompila sin esa variable
  vuelve a 127.0.0.1:3000 (modo adb reverse). El release sigue con URL
  .invalid a proposito.
- No se tocaron GATT, PTT, criptografia ni codigo de backend.
