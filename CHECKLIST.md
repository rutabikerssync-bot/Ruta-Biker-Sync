## P. Guía Operativa de Infraestructura: Cómo levantar y reiniciar el Backend Fastify + PostgreSQL 16

### 1. Estado y Reinicio de PostgreSQL 16 (WSL2 Ubuntu)
PostgreSQL corre nativamente en WSL2 en el puerto `5433` con base de datos `rbs` y usuario `rbs`.
```bash
# Verificar estado del servicio:
wsl -u root -d Ubuntu -e pg_lsclusters

# Iniciar o reiniciar PostgreSQL si está detenido:
wsl -u root -d Ubuntu -e pg_ctlcluster 16 main restart
```

### 2. Iniciar / Reiniciar el Servidor Fastify (Puerto 3000)
El backend compila TypeScript con `npm run build` y corre en Node.js conectándose a PostgreSQL en el puerto 5433:
```bash
# Modo Desarrollo / Daemon en WSL:
wsl -u root -d Ubuntu -e /bin/bash -c "cd /mnt/d/Ruta-Biker-Sync/backend && PORT=3000 PG_TEST_URL=postgres://rbs:rbs_dev_password@localhost:5433/rbs node dist/index.js"

# O mediante npm run dev:
wsl -u root -d Ubuntu -e /bin/bash -c "cd /mnt/d/Ruta-Biker-Sync/backend && npm run dev"
```

### 3. Verificar Salud del Servidor
```bash
# Desde PowerShell o CMD de Windows:
curl.exe -s http://localhost:3000/health
# Respuesta esperada: {"status":"ok"}
```

### 4. Conectar Teléfonos Físicos vía USB (adb reverse)
Para que los dispositivos físicos alcancen el servidor `localhost:3000` a través de USB:
```bash
# TECNO KI5k:
adb -s 098813734B105395 reverse tcp:3000 tcp:3000

# Redmi Note 13 Pro:
adb -s b2c398bb reverse tcp:3000 tcp:3000
```
*(Nota: Al desconectar el cable o reiniciar adb, volver a ejecutar los comandos `adb reverse` anteriores)*.
> **Nota de política de red (auditoría 2026-11-16, B1-1/B1-4):** el acceso HTTP a `http://localhost:3000` vía `adb reverse` es **exclusivo de builds debug** (manifest overlay `src/debug/`). Los builds de release usan exclusivamente HTTPS de producción vía `network_security_config.xml` y `BuildConfig` por variante. No reintroducir `usesCleartextTraffic="true"` en `main`. Trazabilidad de commits de seguridad: `docs/HISTORY_NOTE.md`.
